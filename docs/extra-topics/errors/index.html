Production error codes

Decode minified Mutative production errors, and find the errors and warnings of development builds.

In Mutative's minified production build, full error messages are replaced with numeric codes to reduce the number of bytes sent to users.

When debugging locally, we recommend using the development build. It retains the full error messages, additional validation, and warnings that provide more context about potential problems in your application; see Development and production builds.

If an exception occurs in production, its message reads Minified Mutative error #<code>; visit https://mutative.js.org/docs/extra-topics/errors. Find that code in the table below to recover the message that the development build throws, where <…> stands for a value of the call. The source identifier is provided for contributors working on Mutative itself.

Numeric codes remain stable when an error is removed. Retired codes are reserved so that older production logs can still be decoded.

CodeSource identifierDevelopment message
0InvalidBaseStateInvalid base state: create() only supports plain objects, arrays, Set, Map or using mark() to mark the state as immutable.
1CannotAssignToMapOrSetMap/Set draft does not support any property assignment.
2InvalidArrayIndexOnly supports setting array indices and the 'length' property.
3CannotSetPrototypeOfDraftCannot call 'setPrototypeOf()' on drafts
4CannotDefinePropertyOnDraftCannot call 'defineProperty()' on drafts
5MutateAndReturnEither the value is returned as a new non-draft value, or only the draft is modified without returning any value.
6CannotReturnModifiedChildDraftCannot return a modified child draft.
7CurrentOnNonDraftcurrent() is only used for Draft, parameter: <value>
8StrictModeAccessStrict mode: Mutable data cannot be accessed directly, please use 'unsafe(callback)' wrap.
9UnsupportedMarkResultUnsupported mark result: <result>
10InvalidMarkPlease check mark() to ensure that it is a stable marker draftable function.
11CannotModifyFrozenObjectCannot modify frozen object
12InvalidPatchPath (retired)A generated patch path was invalid. This internal check has been removed; the code is reserved.
13ReservedPatchAttributePatching reserved attributes like __proto__ and constructor is not allowed.
14CannotApplyPatchCannot apply patch at '<path>'.
15ReplacePatchOnSetCannot apply replace patch to set.
16UnsupportedPatchOperationUnsupported patch operation: <op>.
17ApplyOptionsToDraftCannot apply patches with options to a draft.
18OriginalOnNonDraftoriginal() is only used for a draft, parameter: <value>
19RawReturnWithoutValuerawReturn() must be called with a value.
20RawReturnWithExtraArgumentsrawReturn() must be called with one argument.
21ReplaceMutableRootapply() with the mutable option changes the state in place, so a patch cannot replace the root state with another value.

What the errors mean:

  • 0: the base state of create() is not draftable, such as a class instance or a Date; see isDraftable() and marks.
  • 1–4: a recipe assigned a property to a Map or Set draft, assigned a non-index property to an array draft, or called Object.setPrototypeOf() or Object.defineProperty() on a draft.
  • 5 and 6: a recipe changed its draft and returned another value, or returned a changed child draft; see Returning a new state.
  • 7 and 18: current() or original() received a value that is not a draft.
  • 8: in strict mode, a recipe read a value that is not drafted outside unsafe().
  • 9: a mark returned a value other than 'mutable', 'immutable', a function or nothing.
  • 10: a mark answered differently for the same value, such as 'immutable' when Mutative drafted it and nothing when Mutative copied it; a mark must give the same answer for a value each time.
  • 11: code called set(), add(), delete() or clear() on a Map or Set that auto-freeze froze.
  • 13–17 and 21: apply() received a patch that it cannot apply; see Patches that apply() accepts.
  • 19 and 20: rawReturn() was called without an argument or with more than one.

Development-only errors

Development builds also throw these errors, for checks that production builds skip:

MessageCause
Invalid options: <options>, 'options' should be an object.create() or makeCreator() received options that are not an object.
Invalid mark: <mark>, 'mark' should be a function.An array of marks holds a value that is not a function.
You can't use mark and patches or auto freeze together.A mark returned a copy function while patches or auto-freeze are on.
Forbids circular referenceWith auto-freeze, the next state holds an object that holds itself; a longer message names the path of the object that repeats.
Patches with string paths only support string Map keys and no symbol keys, got a key of type '<type>'. Set 'pathAsArray' to true to keep keys of other types.With pathAsArray: false, a patch path would hold a Map key that is not a string, or a symbol key.
A draft cannot be a Map key: its producer revokes it when it ends. Use original(key), current(key) or an id as the key; see https://mutative.js.org/docs/extra-topics/faqA recipe passed a draft to the set() method of a Map draft as the key.
The return value holds a draft in a frozen object or in a value it holds. With auto-freeze, production builds do not search frozen objects for drafts, so do not put drafts there.With auto-freeze, a value that a recipe returned holds a draft inside a frozen object.
