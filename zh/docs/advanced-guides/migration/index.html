从 Immer 迁移

将 Immer API 替换为 Mutative，并检查冻结、补丁、类实例和异步更新的差异。

从 Immer 迁移到 Mutative 主要是替换 API 调用。两者都通过修改草稿生成新状态，并共享未修改的部分。与 Immer 对比列出了完整 API 对应关系和行为差异。

mutative-compat 使用 Immer API 封装 Mutative，可先快速切换，再逐步迁移具体调用。

迁移清单

  1. 将 produce() 替换为 create()，将 produceWithPatches() 替换为开启 enablePatches: true 的 create()，将 applyPatches() 替换为 apply()，将 nothing 替换为 rawReturn(undefined)。current()、original()、isDraft()、isDraftable()、castDraft() 和 castImmutable() 名称不变。
  2. 移除 enableMapSet()、enablePatches() 和 enableArrayMethods() 调用：Mutative 内置支持 Map、Set 和补丁，并原生执行相关数组方法。
  3. 确认是否需要冻结。Immer 默认冻结下一个状态，Mutative 默认不冻结。若代码依赖冻结状态（例如捕获意外修改），请设置 enableAutoFreeze: true。
  4. 将 setAutoFreeze() 和 new Immer() 的全局配置替换为每次调用的选项，或通过 makeCreator() 设置默认值。
  5. 用 mark 选项替换类上的 [immerable] = true。

补丁

使用 Mutative：

传给 produce() 的补丁监听器同样可改为开启此选项，再从 create() 结果读取补丁。两者在缩短数组和修改 Set 中对象时的补丁有所不同：Mutative 默认用 replace 修改 length；设置 enablePatches: { arrayLengthAssignment: false } 后，就会像 Immer 一样逐索引删除。详见对比中的补丁。
