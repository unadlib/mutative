---
title: 共享引用
description: 多条路径指向同一对象时的草稿行为，以及如何保留共享关系。
---

Mutative 支持从根节点到同一节点存在多条路径的结构，即含共享节点的有向无环图（DAG），**但不能包含循环引用**。需要理解草稿处理共享引用时的以下行为。

## 多条路径使用独立草稿 [#independent-drafts-for-multiple-paths]

基础状态的多条路径引用同一对象时，Mutative 会为**每条路径创建独立草稿**。修改一条路径**不会**自动反映到其他路径。

```javascript
import { create } from 'mutative';

const obj = {};
// Same object referenced by two keys
obj.color1 = obj.color2 = { name: 'Red' };

const result = create(obj, (draft) => {
  // ⚠️ Different drafts created for each path!
  console.log(draft.color1 === draft.color2); // false

  draft.color1.name = 'Blue';

  // color2 remains unchanged because it has a separate draft
  console.log(draft.color2.name); // 'Red'
});

console.log(result.color1 === result.color2); // false
// Result: { color1: { name: 'Blue' }, color2: { name: 'Red' } }
```

这是**有意设计的行为**，与 Immer 一致。状态树中的每条路径都有独立的草稿代理。

## 创建共享引用 [#creating-shared-references]

若需在结果状态中**保留或创建共享引用**，必须在更新函数中显式将一个草稿赋给另一个位置。

```javascript
const result = create(obj, (draft) => {
  draft.color1.name = 'Blue';

  // ✅ Explicitly share the reference
  draft.color2 = draft.color1;
});

// Now they share the same reference in the result
console.log(result.color1 === result.color2); // true
// Result: { color1: { name: 'Blue' }, color2: { name: 'Blue' } }
```

## 补丁与原地重放 [#patches-and-in-place-replay]

补丁记录修改所在的路径。`apply()` 会复制这条路径上的对象，因此返回的状态和下一个状态一样，只在这条路径上变化。使用 `mutable: true` 时，`apply()` 改为原地修改路径上的对象；如果状态中有多条路径引用同一个对象或数组，这些路径会一起变化：

```javascript
import { apply, create } from 'mutative';

const list = [1, 2, 3];
const state = { a: list, b: list };

const [nextState, patches] = create(
  state,
  (draft) => {
    draft.a.push(4);
  },
  { enablePatches: true }
);
// nextState: { a: [1, 2, 3, 4], b: [1, 2, 3] }

apply(state, patches, { mutable: true });
// state: { a: [1, 2, 3, 4], b: [1, 2, 3, 4] }, as `a` and `b` hold one array
```

状态中有共享引用时，请不带 `mutable: true` 重放补丁。使用[紧凑数组补丁](/zh/docs/advanced-guides/patches#compact-array-patches)时，更新函数把新数组赋给某个键（例如 `draft.a = draft.a.filter(...)`）也是如此：它的补丁修改旧数组的元素，而不是替换整个数组。赋入内容相同的数组则完全不生成补丁，因此原地重放也不会把共享的数组分开。

## 行为汇总 [#summary]

| 场景 | 行为 |
| --- | --- |
| **基础状态中的共享节点** | 每条路径有**独立草稿**，一条路径的修改**不会**反映到其他路径。 |
| **手动赋值的引用** | ✅ **支持**。`draft.x = draft.y` 在最终状态中创建共享引用。 |
| **用 `mutable: true` 重放补丁** | 经一条路径的修改会出现在**所有**引用同一对象或数组的路径上。此类状态请不带 `mutable` 重放。 |
| **真正的循环引用** | ❌ **不支持**。开发环境开启自动冻结时会主动检测。 |
