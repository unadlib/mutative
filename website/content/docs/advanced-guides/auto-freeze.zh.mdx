---
title: 自动冻结
description: 使用 enableAutoFreeze 深度冻结下一个状态，阻止意外修改。
---

Mutative 默认不冻结下一个状态。开启 `enableAutoFreeze` 后，会通过 `Object.freeze()` 深度冻结下一个状态中 Mutative 会创建草稿的值，意外修改会失败，避免改变其他代码仍在使用的状态。

## 开启自动冻结 [#enable-auto-freeze]

```ts
import { create } from 'mutative';

const baseState = { user: { name: 'Ada' }, tags: ['a'] };

const state = create(
  baseState,
  (draft) => {
    draft.user.name = 'Grace';
  },
  {
    enableAutoFreeze: true,
  }
);

expect(Object.isFrozen(state)).toBe(true);
expect(Object.isFrozen(state.user)).toBe(true);
// The array that the next state shares with the base state is frozen too.
expect(state.tags).toBe(baseState.tags);
expect(Object.isFrozen(baseState.tags)).toBe(true);

// Writing to it throws in strict mode code, such as an ES module.
expect(() => {
  'use strict';
  (state.user as { name: string }).name = 'Linus';
}).toThrow(TypeError);
```

可通过 [`makeCreator()`](/zh/docs/api-reference/makecreator) 为整个应用设置默认值，也可将该选项传给 [`apply()`](/zh/docs/api-reference/apply)，冻结应用补丁后生成的状态。

## 冻结范围 [#what-is-frozen]

自动冻结只冻结 Mutative 会创建草稿的值，与 Immer 一致：

- 下一个状态中沿可枚举键可达的普通对象、数组、Map 和 Set：包括已修改对象的副本、更新函数赋入的值，以及与基础状态共享的对象。共享对象在基础状态中也会被冻结。如果更新函数没有修改任何内容，则返回被冻结的基础状态本身。
- Map 和 Set 的 `set()`、`add()`、`delete()`、`clear()` 方法会抛错；Map 用作键的普通对象、数组、Map 和 Set 也会被冻结。
- [标记](/zh/docs/advanced-guides/mark)使其可创建草稿的值，例如标为 `immutable` 的类实例。

其他值及其内部值保持原样：类实例、无原型对象、日期、正则表达式、函数，以及标为 `mutable` 的值，以便后续更新函数仍可原地修改。typed array、Node.js Buffer 和 DataView 也保持原样，即使标记使其可创建草稿：`Object.freeze()` 冻结有元素的 typed array 会抛错，而且任何视图的字节都无法冻结。2.1 之前，自动冻结也会冻结上述值，并对 typed array 抛错。

```ts
import { create } from 'mutative';

class Account {
  constructor(public balance: number) {}
}

const baseState = { account: new Account(100), history: [100] };

const state = create(
  baseState,
  (draft) => {
    draft.history.push(120);
  },
  { enableAutoFreeze: true }
);

expect(Object.isFrozen(state.history)).toBe(true);
// A class instance is left as it is.
expect(state.account).toBe(baseState.account);
expect(Object.isFrozen(state.account)).toBe(false);

// A mark that makes it draftable freezes it too.
const marked = create(
  baseState,
  (draft) => {
    draft.history.push(130);
  },
  {
    enableAutoFreeze: true,
    mark: (value, { immutable }) =>
      value instanceof Account ? immutable : undefined,
  }
);

expect(Object.isFrozen(marked.account)).toBe(true);
```

已冻结的对象及其内部值会被跳过，因此首次更新冻结状态后，后续更新只需冻结新复制或新增的对象。基础状态也可以预先冻结：修改时，Mutative 像处理其他对象一样复制冻结对象。

在 JavaScript 严格模式代码（包括 ES 模块和类）中，写入冻结对象会抛出 `TypeError`，其他情况下则不生效。冻结的 Map 和 Set 在两种情况下都会抛错。

### 保持类实例冻结 [#keeping-class-instances-frozen]

若要让某个类的实例保持冻结，可以：

- 在创建时冻结每个实例：在没有子类的类的构造函数末尾调用 `Object.freeze(this)`，因为子类无法向冻结的实例添加字段。自动冻结会跳过已冻结的对象，更新函数会替换这类实例，而不是修改它。
- 将该类标为 `immutable`，Mutative 也会为其实例创建草稿，更新函数修改的是实例的副本。Mutative 无法为含私有字段（`#field`）的实例创建草稿：通过草稿读取这类字段时，其方法会抛错，副本也没有这些字段。这类实例应在构造函数中冻结。

## 开发环境检查 [#development-checks]

开发构建会拒绝在自动冻结的对象之间存在循环引用的下一个状态，即对象通过其内部值直接或间接持有自身。Mutative 不支持此类结构，详见[共享引用](/zh/docs/extra-topics/shared-references)。生产构建跳过该检查。

开启自动冻结后，生产构建在[返回值](/zh/docs/api-reference/rawreturn)中搜索草稿时也会跳过冻结对象，以及自动冻结保持原样的对象（如类实例），所以返回之前已冻结的状态开销很小。开发构建仍会搜索，并在发现草稿时抛错。

由于 2.1 之前自动冻结会冻结所有对象，开发构建在自动冻结首次跳过不创建草稿、且有自有可枚举属性的对象（如带字段的类实例）时会警告一次。将这类值标为 `mutable` 可关闭该警告。

## 成本与建议 [#cost-and-recommendation]

冻结需要访问所有要冻结且尚未冻结的对象，每次更新都有开销，宽对象和大数组尤其明显。在[基准测试](/zh/docs/getting-started/performance)所选的大多数工作负载中，默认冻结的 Immer 开启自动冻结时比关闭时更慢；Mutative 默认关闭此功能。

<Callout type="idea">
建议在开发环境开启自动冻结以发现意外修改，在生产环境关闭以提高性能：`makeCreator({ enableAutoFreeze: process.env.NODE_ENV !== 'production' })`。如果其他代码依赖冻结状态，则应在生产环境保留。
</Callout>

返回自定义浅拷贝函数的[标记](/zh/docs/advanced-guides/mark)不能与自动冻结一起使用。[`current()`](/zh/docs/api-reference/current) 始终返回未冻结的快照，即使开启了自动冻结。TypeScript 会将 `enableAutoFreeze: true` 时 `create()` 的返回类型标为属性只读的 `Immutable<State>`，自动冻结保持原样的类实例在类型上也是只读的。
